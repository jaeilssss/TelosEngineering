현재 프로젝트 루트의 `SPEC.md`를 기준으로 구현을 수행한다.

이 스킬은 `impl` 오케스트레이터로 동작한다. 구현은 기본적으로 현재 세션에서 진행한다.
`telos:impl-worker` 서브에이전트는 탐색 범위가 넓거나, 영향 반경이 불명확하거나, 인수 기준을
코드에 매핑하는 과정이 커서 메인 컨텍스트에 저가치 탐색 로그가 많이 쌓일 때만 사용한다.
워커를 쓸 때는 오케스트레이터가 이미 선택한 모델/경로를 다시 묻지 말고 그대로 전달한다.

## 사전 게이트

가능하면 먼저 `telos update-status claude --project-root .`를 실행한다. 메시지가 나오면 업데이트 권장을 먼저 보여준다.

`SPEC.md`가 현재 작업 디렉토리에 존재하는지 Bash 툴로 확인한다.

존재하지 않으면 **즉시 중단**하고 아래 메시지를 출력한다:

```
🚫 SPEC.md가 없습니다.
구현 전에 /telos:spec으로 인수 기준을 먼저 확정하세요.
```

SPEC.md의 상태가 `draft`이면 마찬가지로 중단한다:

```
🚫 SPEC.md가 아직 draft 상태입니다.
/telos:spec을 완료해 frozen 상태로 만든 뒤 다시 실행하세요.
```

## 모델과 워커 선택

SPEC.md가 `frozen` 상태임을 확인했으면 구현을 분류한다. `Expected Change Surface`, `Verification Plan`, `Risk Profile`, `Spec baseline`도 읽는다. baseline이 현재 브랜치/리비전과 달라 작업에 영향을 줄 수 있으면 차이를 보여주고 구현 전 사용자에게 spec 재확인을 요청한다.

- 먼저 `SPEC.md`로 1차 범위와 리스크를 읽는다.
- 그 다음 실제 코드베이스를 확인해 그 판단을 확인하거나 보정한다.
- Routine: 작고 국소적이며 저위험인 변경
- Complex: 넓은 설계, 마이그레이션, 인증/결제, 데이터 손실 위험, 동시성, 아키텍처 불명확

그 다음 AskUserQuestion 툴로 아래 선택지를 표시한다:

- 질문: "구현을 현재 세션의 기본 모델/프로필로 계속할까요?"
- 선택지 1 — **계속 진행** (추천): Routine 작업에 적합. 현재 세션 프로필을 유지하고 현재 세션에서 구현한다.
- 선택지 2 — **더 강한 모델로 재시작**: Complex 또는 고위험 작업에 적합. 사용자가 Claude를 더 강한 모델/프로필로 재시작한 뒤 `/telos:impl`을 다시 실행하게 한다.
- 선택지 3 — **취소**

현재 세션에서 계속한다면 메인 세션에서 바로 구현한다.
변경이 작고 코드 경로가 이미 명확하면 메인 세션에서 끝까지 수행한다.
탐색 범위가 넓거나 영향 반경이 커서 메인 컨텍스트를 오염시킬 가능성이 클 때만
`telos:impl-worker` 서브에이전트를 호출해 구현을 위임한다. 이때 워커가 모델 선택이나
preflight를 다시 묻지 않도록 필요한 컨텍스트를 함께 넘긴다.

워커 프롬프트/입력에는 반드시 포함할 것:
1. 현재 디렉토리의 `SPEC.md` 전체 내용과 AC를 파악할 것
2. 현재 오케스트레이터가 이미 선택한 모델/경로 결과를 다시 묻지 말 것
3. 관련 코드베이스를 파악한 뒤 AC를 하나씩 충족하는 방향으로 구현할 것
4. 관련 `CLAUDE.md`와 작업 중인 파일의 dirty worktree 제약을 존중할 것
5. 구현 완료 후 요구사항 요약, 확정된 결정, 현재 계획/실행 상태, 변경 파일, AC 대응 여부,
   실행한 검증, 막힌 질문, 검증 공백, scope drift와 사용자 확인, 다음 단계 handoff 파일 인덱스, commit reference를 구조적으로 반환할 것

구현 워커에는 전체 대화 로그를 넘기지 않는다. `SPEC.md`, 관련 파일 경로, 제약, 꼭 필요한
결정만 넘긴다. 워커가 스펙 충돌이나 인수 기준 부족을 보고하면 추측하지 말고 `/telos:spec`
으로 되돌린다.

완료 전에는 변경 파일과 의존성·API·스키마 변경을 Expected Change Surface와 비교한다. 허용되지 않았거나 AC에 매핑되지 않는 변경은 사용자 확인 없이 범위를 넓히지 않는다. Verification Plan의 프로젝트 명령은 `/telos:eval`을 위해 보존하며, 언어별 기본 명령으로 바꾸지 않는다. 선택된 Risk Profile의 검사는 일반 테스트가 대신 해준다고 가정하지 말고 직접 충족한다.

메인 세션으로는 긴 탐색 로그나 파일 전문 대신, 다음 지시에 필요한 짧은 구조화 요약과 파일
인덱스만 남긴다.

## 완료 안내

Agent 구현이 끝나면 반드시 아래 메시지를 출력한다:

```
✅ 구현 완료.
/telos:eval 로 인수 기준을 채점하세요.
```
